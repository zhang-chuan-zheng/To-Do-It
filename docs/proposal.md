# To Do It 需求文档

> 文档状态：首版需求基线、0.2.1 安装/更新界面与部署方案已确认（v1.3）
> 目标平台：Windows 10 1809（Build 17763）及以上、Windows 11  
> 推荐开发基线：C++20、Qt 6.11.2、Qt Quick/QML、MSVC x64、Ninja、CMake 3.24+

## 1. 产品概述

To Do It 是一款离线优先、单用户使用的 Windows 桌面任务清单软件。事项与附件使用不依赖网络；只有用户主动打开维护工具检查 GitHub 更新时才访问网络。软件通过树形事件组织父事项与子事项，以统一的透明磨砂玻璃视觉呈现任务、备注、附件、状态、时间、重要程度和完成情况。

首版不提供账号、云同步、多设备同步、macOS 或 Linux 支持。

本草案只记录已经确认的需求。仍存在歧义或需要产品决策的内容统一标为“待确认”，确认前不得作为实现假设。

## 2. 技术与工程约束

### 2.1 UI 技术

- 使用 Qt Quick/QML 构建 UI，C++ 实现领域模型、持久化、平台能力和复杂控制逻辑。
- Qt Quick 更适合本产品的大量自定义样式、圆角、展开动画、递归组件和主题令牌。
- QML 组件、页面、对话框、效果和样式分别存放。
- Qt Quick 不使用网页 CSS 作为主要样式机制。颜色、渐变、背景图片、圆角、字号、间距和透明度通过独立 QML 主题令牌及组件样式实现。
- 主题系统使用集中令牌和可扩展接口。当前版本只启用原石墨磨砂主题，不加载此前试制的液态玻璃材质，也不在标题栏提供主题切换控件；未来仍可通过集中令牌与资源配置扩展颜色、渐变和背景图片。
- Qt 基线采用 Qt 6.11 系列，当前固定 Qt 6.11.2 的 `msvc2022_64` Kit；它覆盖目标 Windows 10/11 平台，并具有较新的扩展客户区能力。
- 构建使用 CMake 3.24 或更高版本。用户提供的“CMake 0.0.17”不像 CMake 本体版本，正式开发前须以 `cmake --version` 的结果为准。
- 不使用当前环境中 Anaconda 附带的 Qt 5.15.2，也不再使用 MinGW Kit。Qt 库、编译器架构和构建环境必须属于同一套经验证的 MSVC x64 配置，禁止混用 MinGW 目标文件或其他 Qt 安装。

### 2.2 Windows 磨砂玻璃

- 主窗口及全部视觉组件保持一致的透明磨砂玻璃语言，不得出现明显风格割裂。
- 窗口采用无边框设计，并保留最小化、最大化/还原、关闭、标题栏拖动、双击最大化及边缘缩放能力。标题栏普通单击只负责释放输入焦点；只有按住并移动超过系统拖动阈值后才调用系统窗口移动，禁止用一次单击启动原生拖动或遗留指针捕获。
- QML 负责透明表面、圆角、描边和遮罩；窗口最外层的实色回退与环境光必须先合成为单一背景纹理，再使用与窗口圆角一致的 alpha 蒙版裁剪，禁止仅依赖 `Rectangle.clip`（该属性只按矩形边界裁剪）而让装饰层泄漏到透明四角。窗口后方内容的真实模糊由 Windows 桌面合成器渲染。
- 首选固定 QWindowKit 1.5.0，只启用 `Core` 与 `Quick` 模块，用其 Qt/QML 接口管理无边框窗口、标题栏命中测试、Snap Layout 与系统背景属性；禁用 Widgets、示例和测试模块以减少体积。
- QWindowKit 仍会在内部调用 Win32/DWM，因为 Qt 或任何辅助库都无法绕过 Windows 系统接口取得真实桌面背景模糊。此类调用主要发生在窗口创建和状态改变时，不进入每一帧的业务循环；实际模糊由系统合成器完成，不是主要性能瓶颈。
- 为保持轻量，不为每个事件行或原子字段执行独立实时 ShaderEffect 模糊；全窗口只使用一个系统背景层，小型组件在其上绘制统一的透明材质、同心轮廓和高光，只有高层弹窗等确需分离前后内容的表面才截取并模糊应用内部背景。
- 此前试制的青色液态玻璃材质、专用 Logo、材质层及运行时滑动开关已取消，程序不得再注册或加载这些资源。石墨主题继续使用统一透明表面；下拉框、调色盘和其他高层弹层仍可对应用内部背景做有限模糊，以保证前景文字清晰。
- Windows 11 Build 22621+ 可使用官方 Desktop Acrylic；Windows 10 只能使用 QWindowKit 封装的非公开 DWM blur 路径，无法获得与 Windows 11 官方 Acrylic 相同的兼容性保证。
- 最终兼容策略为：Windows 11 22H2+ 使用官方 Acrylic；Windows 10 使用 QWindowKit 的 DWM blur；用户明确接受 QWindowKit 在内部间接调用 Win32/DWM。
- 系统禁用透明效果或环境不支持磨砂时，软件仍须运行并保留全部功能，显示实色系统背景，并在诊断信息中记录磨砂不可用原因；不得用高成本截图或 Shader 冒充真实背景模糊。

### 2.3 分层结构

- `domain`：事件实体、树结构和业务规则。
- `application`：创建、编辑、筛选、排序、拖拽、保存等用例。
- `infrastructure`：CSV、配置、附件引用、备份和迁移。
- `platform/windows`：DWM、无边框窗口、DPI 和系统文件调用。
- `presentation/controllers`：QML 可访问的视图模型和控制器。
- `presentation/qml`：页面、组件、对话框、视觉效果和样式。
- `updater`：独立更新与数据格式迁移。
- `tests`：业务、持久化、迁移和关键交互测试。
- 详细目录、文件和函数职责见 `docs/structure.md`；新增、删除、重命名文件或改变公开职责时，必须同步更新该文档。

- 已确认 `0.0.17` 是 `twxs.cmake` 编辑器扩展版本，不是 CMake 程序。继续使用 VS Code 时建议禁用功能重叠的 `twxs.cmake`，保留 Microsoft CMake Tools。
- Qt Online Installer 已在源码树之外的 `D:/Qt/` 安装 Qt 6.11.2 `msvc2022_64`、CMake 3.30.5、Ninja 1.12.1、Qt Creator 和 Qt Design Studio；Qt Kit 固定为 `D:/Qt/6.11.2/msvc2022_64`。
- C++ 编译器由 `D:/Microsoft Visual Studio/18/Community` 的 x64 开发环境提供，当前检测为 MSVC 19.51。VS Code 脚本必须先调用 `VsDevCmd.bat` 注入当前进程环境，再使用 Ninja 预设；该过程不得修改系统环境变量。
- VS Code 负责 C++/CMake 日常开发，Qt Creator 可使用同一 MSVC Qt Kit 进行构建和调试，Qt Design Studio 用于编辑和预览 `presentation/qml`。三者必须指向同一 Qt 6.11.2 MSVC Kit，不能分别生成不兼容的构建缓存。
- 当前系统 PATH 中的裸 `qmake` 属于 Anaconda Qt 5.15.2，因此项目配置、构建、测试和部署必须调用 Qt 工具的绝对路径或经验证的项目脚本；禁止依赖裸 `qmake`，也禁止把旧 MinGW 产物带入 MSVC 构建目录。
- Qt SDK 不提交仓库，也不整体放入最终安装包。本机不提交的 `CMakeUserPresets.json` 固定 `CMAKE_PREFIX_PATH`、Ninja 和 MSVC 编译器选择；Qt 自带 CMake 负责读取预设。切换编译器或 Qt Kit 时必须使用新的构建目录。
- 如确需“项目本地 SDK”，可以安装到 `[ProjectRoot]/.toolchains/Qt/` 并整目录忽略；该方案占用大、容易被误备份或误打包，首选仍是外部共享 SDK。
- 开发工具链位置与最终软件部署相互独立：用户电脑不需要预装 Qt SDK。

### 2.5 当前工程基线

- 当前应用发布目标为 0.2.1，事件与设置架构仍保持 v1；本次补丁版本修复安装器界面和 Qt 运行库部署，不改变 `event.csv` 列结构，也不新增数据迁移步骤。当前项目已建立 Domain、Application、Infrastructure、WindowsPlatform、Presentation 与独立 UpdateCore CMake 目标。程序启动时由 C++ `CsvEventRepository` 严格读取 `event.csv`，再由 `EventDataController` 将事件快照提供给 Qt Quick 主页面；事项列表不包含 QML/C++ 内置示例事件。CSV UTF-8 解码会先保持源字节存活并立即实体化为 `QString`，避免惰性转换引用临时对象而把合法的 `schema_version=1` 误判为不支持。有效的标题、重要度、时间、状态、备注、文件/文件夹附件、右键新建子事项、右键删除完整子树与树拖放修改只标记内存快照为待保存；每 5 分钟仅在确有修改时原子写回，正常关闭前再检查并同步刷新。离线名言 JSON 已作为 QML 资源打包并由 C++ 控制器校验、随机选择；主窗口非最小化且可见时每 2 分钟换句一次并执行上下滚动缩放过渡，最小化期间暂停计时。持续时间会在时间/状态提交后立即重算，并以单个一分钟计时器批量刷新未完成事项的显示值。当前只加载石墨磨砂主题，液态玻璃材质与切换控件已移除；底部打赏入口继续保留。Windows EXE 与 Qt IFW 安装器使用可替换的多尺寸 ICO，标题栏/窗口运行期图标使用对应 SVG。Release 安装部署、GitHub Pages 在线仓库、离线更新包、版本清单、迁移前备份、v1 完整校验和按稳定字段名的通用迁移源码已经写入；正式运行期资源定位器、真实打赏二维码、普通保存备份、数据恢复和平台磨砂仍未完成。
- VS Code 的工作区任务、Qt Creator Kit 与命令行脚本共用根 CMake 工程和 `local-dev`/`local-release` 预设；Qt Design Studio 通过根 `ToDoIt.qmlproject` 编辑与预览 `src/presentation/qml`，不替代正式 CMake 构建。
- 本机工具链组合为 Qt 6.11.2 `msvc2022_64`、CMake 3.30.5、Ninja 1.12.1、x64 MSVC 19.51.36256.0。此前应用壳基线曾完成 Debug 编译和启动排错；本次 0.2.1 安装器、部署布局和清单改动按用户要求仅写入文件，尚未重新配置、编译、打包、运行或测试。

## 3. 数据模型

### 3.1 事件字段

`event.csv` 使用 UTF-8（带 BOM）和 RFC 4180 引号转义，每行表示一个事件。固定列如下：

| 列 | 含义与约束 |
| --- | --- |
| `schema_version` | 数据格式版本，用于更新迁移 |
| `event_id` | 永不重复的 UUID；更新和拖拽不得改变 |
| `parent_id` | 父事件 UUID；一级事件留空 |
| `sibling_order` | 同一父事件下的手工顺序，独立于临时排序 |
| `title` | 事项名称；去除首尾空白后不得为空 |
| `importance` | 仅允许 `1、3、5、7、9` |
| `start_at` | ISO 8601 日期时间，精确到分钟并包含本地 UTC 偏移 |
| `completed_at` | 未完成时为空；已完成时必填 |
| `status` | 空值等价于“进行中”；也可为“已完成”“已取消”或自定义值 |
| `note_html` | 仅允许加粗、字体颜色、段落与换行的受限 HTML |
| `attachments_json` | JSON 字符串数组，保存附件原文件或文件夹的绝对路径；文件夹路径保留结尾目录分隔符 |
| `created_at` | 创建时间，用于诊断和迁移校验 |
| `updated_at` | 最近成功保存时间 |

- CSV 字段可安全包含逗号、双引号、换行、中文和 HTML；写入时统一转义，读取时禁止用简单字符串分割。
- 富文本载入前执行白名单清理，拒绝脚本、远程资源、任意 CSS 和未知标签。
- 文件和文件夹附件都只记录路径，不复制、不移动原内容。
- 应用配置不混入事件 CSV，保存到安装目录下的 `data/config/settings.json`，包含配置格式版本、窗口尺寸/位置、主题参数、最近筛选条件、搜索范围、排序键和其他用户偏好；更新时与事件数据一起迁移。
- 首次加载采用整文件严格校验：BOM、表头、列数、UTF-8、版本、UUID、父引用、环、重要程度、时间、附件 JSON 和备注安全约束任一失败时，本次加载整体失败，不展示部分数据，也不以内置事项或伪造空数据替代。页面底部必须显示可定位到文件、行号和列名的错误。
- 当前开发配置可通过进程环境变量 `TODOIT_EVENT_FILE` 指定本地测试文件；该变量只用于开发/诊断，不改变正式安装路径规则。没有覆盖时始终读取可执行文件目录下的 `data/event.csv`，不得依赖进程工作目录。
- 启动目标路径尚无 `event.csv` 时，程序自动创建父目录，并通过临时文件提交一个仅含 UTF-8 BOM 与正式 13 列表头的空事件文件；该初始化只允许发生在文件确实不存在时，已有文件无论有效或损坏都不得覆盖。目录或文件无法创建时按加载失败显示路径诊断。

### 3.2 时间

- 开始时间与完成时间精确到分钟，界面统一显示和输入为 `YYYY-MM-DD HH:mm`。
- 时间编辑器使用一个连续的固定格式 `0000-00-00 00:00`，而不是五个相互隔离的输入框，也不使用会强制跳过分隔符光标位置的 Qt 输入掩码，不显示 `YYYY/MM/DD` 等占位格式文字。组件自行维护 12 个数字槽：每输入一位数字，文本光标前进到下一数字槽并自动越过横线、空格和冒号；用户可用鼠标把光标放到任意数字位或分隔符的前后（包括年份最后一位数字之后、第一条横线之前），也可用键盘左右方向键逐字符跨年、月、日、时、分移动。
- 月限定为 `1–12`，小时为 `0–23`，分钟为 `0–59`；日期还必须根据月份及闰年校验实际天数。无效或未填完整的时间不得提交，并以字段错误描边和底部提示说明原因。
- 新建事件的开始时间默认为当前时间，并允许手动修改。
- 状态从非完成改为“已完成”时，自动将完成时间设为当前本地时间；用户随后可以在连续时间输入框内修改。若开始时间仍在未来，则拒绝完成状态并提示原因。
- 已完成事项重新改为未完成状态时，清空完成时间。
- 已完成事项的持续时间为完成时间减开始时间。
- 未完成事项的持续时间为当前时间减开始时间，并以一分钟为频率更新。
- 开始时间、完成时间或状态提交成功后，持续时间必须立即重算；一分钟周期刷新只更新显示值，不触发自动重排。
- 显示格式为“xxx 天 xx 时 xx 分”。
- 完成时间早于开始时间时禁止保存，并在事件组件与底部状态栏显示错误。
- 完成时间晚于当前时间时同样禁止保存；用户只能手动调整到“开始时间至当前时间”区间。
- 开始时间允许位于未来；到达开始时间前持续时间列显示“尚未开始”。

### 3.3 状态

- 初始显式状态包含“已取消”“已完成”。
- 未选择状态或状态字段不显示时，业务状态按“进行中”处理。
- CSV 中“进行中”可保存为空；界面状态列使用弱化文字显示“进行中”，保证用户能理解当前状态。
- 状态既可从下拉选项选择，也可手动输入。
- 事项编辑下拉列表动态汇总当前全部事件中已存在的状态。
- 只要至少存在一个空状态事件，事项编辑下拉列表和顶部状态筛选器就必须把其有效状态“进行中”列为可选项；空字符串本身不作为可见状态选项。
- 顶部筛选器额外包含“全部事项”和“未完成事件”。
- “未完成事件”指所有非“已完成”状态。
- 顶部筛选器默认选择“未完成事件”。
- 每个事件的状态相互独立；改变父事件状态不得自动改变任何子孙事件。
- 筛选任意状态时，只按每个事件自身状态判断是否匹配。匹配的事件连同完整祖先链一起显示，祖先的实际状态不影响其作为上下文显示；不匹配且不是必要祖先的子孙事件隐藏。
- 此规则同样适用于“未完成事件”：已完成的父事件可以作为匹配子事件的祖先显示，不再隐藏整棵子树。
- 该条是最终规则，并覆盖较早提出的“已完成父事件在未完成筛选中隐藏整棵子树”规则。
- 筛选或搜索后，所有可见层级按当前可见顺序重新编号。

### 3.4 重要程度

- 重要程度包含 1、3、5、7、9 五个等级。
- 界面使用渐变进度条表现，不显示具体数字。
- 默认等级为 5；1 表示最低、9 表示最高；颜色从低等级冷色平滑过渡到高等级暖色。

### 3.5 父子关系

- 支持无限级父子事件。
- 允许把事件 A 拖到事件 B 上，将 A 及其完整子树移动到 B 下。
- 允许把任意事件拖回一级或移动到其他任意合法层级。
- 禁止把事件拖到自身或自身后代下，防止形成环。
- 父事件有直接子事件时，在事项名称列最右侧显示“已完成直接子事件数 / 直接子事件总数”，例如 `2/7`。
- 比例只统计直接子事件，不统计更深层后代；分子仅包含“已完成”事件，分母包含所有未取消的直接子事件，自定义状态计入分母，“已取消”不计入分母。
- 无直接子事件时不显示；有直接子事件但全部取消时显示 `0/0`。
- 比例文字字号略小于事项名称，显示区域固定宽度。

## 4. 页面结构

### 4.1 顶部标题区

从左到右包含可替换的软件 Logo、软件名称、搜索框、最小化按钮、最大化/还原按钮和关闭按钮；不显示主题切换开关。顶部栏高度由原始 `50 px` 压缩到约 `46 px`；Logo 保持 `28 px`，搜索圆形锚点保持 `32 px`，三个窗口按钮保持 `30 px`，全部沿同一垂直中心线布置，在缩短高度的同时保留原图标视觉大小和约 7–8 px 上下留白。无边框窗口的四条边及四个角必须提供符合系统光标方向的鼠标缩放热区，并使用 Qt 的系统窗口缩放接口；最大化或全屏时禁用这些热区。开发期界面 Logo 放在 `assets/logos/custom/app.svg`，存在时由 CMake 优先打包，不存在时回退到 `assets/logos/default/app.svg`。Windows EXE 与 Qt IFW 安装器图标放在 `assets/logos/custom/app.ico`，缺失时回退到 `assets/logos/default/app.ico`；替换 SVG 或 ICO 后均需重新配置 CMake，Windows 原生图标必须使用多尺寸 ICO。

### 4.2 信息与筛选区

- 左侧为单行随机哲学名言区域；相对于上一版适当缩短其最小宽度，为右侧完整统计文字留出空间。
- 中部为固定位置的状态筛选下拉框。
- 右侧为独立统计框，固定显示“`N 项待完成 · M 项已完成`”；待完成只统计既非“已完成”也非“已取消”的事项，已完成只按事项自身实际状态统计，父子事项分别计数。
- 信息与筛选区整体高度压缩到约 `40 px`，三部分保持等高和同一垂直中心线。
- 顶部状态筛选、搜索条件和事项状态的所有下拉弹层，必须对其覆盖的应用页面区域进行模糊并叠加足够不透明的深色石墨遮罩；下层文字和图形不得透过弹层干扰选项阅读。
- 状态筛选和搜索只改变列表可见范围，不改变右侧“待完成/已完成”全局计数；仅作为祖先上下文显示的事项仍只按自身真实状态计算一次。

### 4.3 事项主体区

主体采用表格视觉，表头依次包含序号、事项名称、重要程度、开始时间、完成时间、项目状态和持续时间。表头不套独立标签框，使用轻微纵向分隔标示列边界；每条事项保留完整圆角外框，外框内的每个字段另有统一细描边圆角框。事项列表的垂直滚动条固定在主体区域最右侧，不得出现在序号列或事项卡左侧；滚动条轨道的顶部和底部必须分别锚定可滚动视口的顶部和底部，完整覆盖整个滚动区域，高度不得由滑块的隐式尺寸决定。滚动条宽约 `9 px`，滑块按可见内容比例显示且最小不低于轨道的 `12%`，轨道、滑块、悬停和按下状态均使用当前主题颜色。事项列表之后紧贴显示单一完整的“添加事项”按钮。

### 4.4 底部帮助区

- 页面底部显示当前悬停或点击组件的解释信息。
- 提示优先级为：正在编辑的组件 > 最近点击并固定的组件 > 当前悬停组件 > 默认操作提示。
- 双击附件成功提交给系统打开后显示：“`XXX已打开，请注意所有修改均将被保存！`”。其中 `XXX` 为附件文件名。
- 底部帮助文字右侧依次显示无背景、不可点击的“打赏一下”纯文字与向右箭头，以及独立的圆角正方形打赏图标按钮；只有打赏图标按钮属于点击区域，点击后在右下方打开与当前主题一致的打赏图片弹层。首版使用明确标注的占位图，正式二维码通过独立图片资源键替换，不写入业务代码。

## 5. 搜索与筛选

- 搜索框收起时只显示搜索 Logo 和固定圆形区域。
- 鼠标悬停圆形区域时，输入区域向右展开，Logo 与圆形区域不移动。
- 仅由普通悬停触发展开时，鼠标离开搜索框 800 ms 后自动收起；该值作为配置项保留，原型体验测试后可以调整。用户点击搜索框以外的其他输入框或空白区域时，搜索输入必须立即失焦；搜索内容为空且下拉弹层未打开时立即收起，不再等待 800 ms。已有非空搜索条件时保持展开，避免隐藏当前过滤状态。
- 输入和编辑期间必须保持展开，不得因失焦判断错误而隐藏正在输入的内容。
- 搜索条件下拉框包含“全部、事项名称、备注、附件名称”，默认选择“全部”。
- 搜索文本在搜索胶囊中垂直居中；条件选择器不使用独立内边框，只保留完整选项文字和下拉箭头，其弹层沿用搜索栏的石墨玻璃配色且不得省略选项文字。
- 标题与搜索胶囊之间保留约一个“Logo + 软件名称”视觉组宽度的留白，展开搜索时只向右占用空间，不贴靠软件名称。
- 默认窗口下搜索胶囊展开宽度为约 `460 px`，较上一版增加约三分之一；收起后的圆形搜索锚点尺寸和位置保持不变。
- 搜索只在顶部状态筛选器得到的事件集合内执行，不得绕过当前状态筛选。
- 首版目标规模不超过 1000 个事件，因此搜索随每次文本变化实时执行；模型层合并同一 UI 事件循环内的重复刷新，不使用肉眼可感知的固定延迟。
- 搜索命中的子事件必须连同祖先链显示；其他不匹配且不是必要祖先的事件隐藏。
- 搜索只改变列表可见结果，不改变右侧全局“待完成/已完成”统计。

## 6. 事项显示与交互

### 6.1 层级编号

- 编号仅反映当前显示顺序，与创建顺序无关。
- 一级事件使用阿拉伯数字，从 `1` 开始。
- 编号样式按层级循环：第 `3n+1` 层使用阿拉伯数字（`1, 2, 3...`），第 `3n+2` 层使用小写拉丁字母（`a, b...z, aa...`），第 `3n+3` 层使用大写罗马数字（`I, II, III...`）。因此相邻父子层的编号规则不重复，并可支持无限层级。
- 排序或筛选后重新编号，仍按当前从上到下顺序由小到大显示。

### 6.2 排序

- 事项名称、重要程度、开始时间、完成时间和持续时间表头右侧提供上、下排序箭头。
- 点击上箭头正序，点击下箭头逆序；再次点击当前方向取消排序并恢复点击排序前的顺序。
- 允许同时选择多个排序字段，按首次选择顺序形成排序流水线；先选择的字段优先级更高，后续字段只细分此前字段值相同的项目。
- 排序控件不显示 `1、2、3、4` 等优先级徽标，避免遮挡箭头；当前生效方向使用带主题强调色的圆形底和高不透明度箭头，未生效方向保持低对比。上下箭头组成约 `22 px` 高的紧凑控件，视觉范围以相邻表头文字的顶部和底部为界，只允许轻微超出，不得形成明显的上下空隙。
- 排序只重排同一父事件下的兄弟事件，并递归应用于每组兄弟，禁止拆散父子树。
- 每个排序字段执行前，控制器保存所有兄弟组的输入顺序检查点；执行后保存输出顺序。排序必须稳定，全部活动字段均相等时保持持久化的 `sibling_order`。
- 已存在字段再次被操作时，不把重复字段追加到末尾。控制器恢复该字段第一次执行前的检查点，更新其方向，再按原顺序重新执行它之后仍然有效的字段。
- 示例 `A-B-C-D-B`：第二次操作 B 时恢复“第一次 B 之前”的 A 排序结果，重新执行 B，再依次执行 C、D；B 的原优先级位置不变。
- 取消字段 B 时恢复 B 之前的检查点，移除 B，再按顺序执行 C、D；全部字段取消后恢复 `sibling_order`。
- 首版排序历史只用于内部正确恢复和重算，不提供独立的可见撤销按钮。
- 完成时间升序排列时，完成时间为空的事件放在所有有完成时间的事件之后；降序排列时，空完成时间事件放在所有有完成时间的事件之前。
- 一分钟持续时间刷新只更新显示值，不触发自动重排，避免正在悬停或编辑的事件突然移动。名称、重要程度或状态编辑提交后，如果影响活动排序字段，则从最早受影响检查点重新排序。
- 持续时间排序生效时，开始时间或完成时间的有效修改先立即更新字段和持续时间，但不立刻改变事项位置，并创建一次待排序请求。只有全部事项的所有可编辑内容都结束编辑并连续保持 500 ms 后，才按当前完整排序流水线重排。
- 上述 500 ms 内，只要任一事项的任一可编辑内容重新进入编辑状态，或再次提交名称、重要程度、开始时间、完成时间、状态、备注、附件等修改，就必须停止并重置本次倒计时且不得重排；全部编辑结束后重新从 500 ms 开始计算。连续编辑多个事项或多个字段时，只在最后一次编辑结束后执行一次重排。
- 已有排序生效时，用户提交可能改变顺序的字段后，事项卡使用约 260 ms 的快速位置动画移动到新位置；动画必须保留同一个事项委托和编辑上下文，使用户能够目视追踪，禁止通过清空并重建整张列表造成瞬移或闪烁。

### 6.3 拖拽与顺序

- 拖动事件时携带该事件的完整子树。
- 事件 B 行的上部投放区表示“插入到 B 前”，中部表示“成为 B 的子事件”，下部表示“插入到 B 后”。三种视觉语义不得混用：只有中部子事项投放区允许整张 B 卡显示强调背景与高亮边框，并且整卡高亮出现时，松开必须生成 B 的子事项；上部/下部同级投放区不得高亮整卡，只能在对应外边缘显示清晰的 3 px 插入线。普通非拖拽悬停仍可使用原卡片悬停高亮。
- “插入到 B 前/后”使 A 成为 B 的同级事件；该逻辑同样用于将 A 从原父事件中拖出。
- 主列表提供一级投放区，可把任意事件及其子树移回一级。
- 禁止投放到自身或自身后代；非法区域显示禁止指针且不改变数据。
- 有活动排序字段时仍允许“成为子事件”“移回一级”和“插入到 B 前/后”。前插/后插只修改持久化手工顺序；当前画面继续遵循活动排序，全部排序取消后显示新的手工顺序。
- 处于筛选或搜索时同样允许“插入到 B 前/后”；A 在完整未筛选的兄弟顺序中紧邻 B 插入，其他被隐藏兄弟保持原相对顺序。
- 成功移动后重算受影响父节点的 `sibling_order`、可见序号和直接子事件比例，并以一次原子保存落盘。
- 拖动开始后原位置保留低对比占位，并显示一张跟随指针的紧凑浮动事项卡；目标行继续用整卡高亮或插入线表示命中。进入目标中部时，浮动卡以约 150 ms 轻微收窄并提示“将成为子事项”；松开后，真实事项卡以约 260 ms 同时过渡横向缩进、宽度和纵向位置，平滑落入目标的子事项位置。减少动画模式下允许把这些时长归零，但业务结果不得改变。
- 整张事项卡都是拖动命中区域：备注折叠时覆盖顶部事项行，备注展开后继续覆盖附件栏、备注标题、工具栏、正文和详情框内空白。普通单击仍交给原控件；只有按住左键并移动超过拖动阈值才取得拖放手势。从详情区开始拖动时，拖拽热点使用相对于完整事项卡的按下坐标，不得沿用顶部行坐标造成目标命中偏移。

### 6.4 单个事件组件

- 每个事件由一个整体组件承载全部信息。
- 不同事件允许使用完全相同的事项名称，持久化、编辑、拖拽和删除均以 UUID 唯一识别，禁止以名称作为主键。
- 子事件序号起点与父事件事项名称对齐。
- 父事件事项名称宽度与子事件“序号组件 + 事项名称组件”的总宽度保持一致。
- 整个列表同一时间最多展开一个事项的备注。首次悬停事项约 240 ms 后展开；从一个事项移到另一个事项时，只有在新事项内稳定停留 240 ms 才提交旧编辑并切换，快速经过其他事项不得抢走焦点。旧备注与新备注不得同时展开，鼠标离开当前事项且没有编辑时约 420 ms 后收起；展开、切换和收起计时器触发时必须重新核对委托当前的真实悬停状态，不得仅依赖动画开始前缓存的事件 ID。
- 备注展开/收起使用约 220 ms 的先慢后快再慢高度动画；动画期间锁定本次目标事项，不响应因列表位移短暂经过的其他事项。展开后的“事项行 + 备注”整体区域必须覆盖触发切换时的鼠标位置，避免布局位移造成重复展开、无法收起或误点。该动画只用于详情整体展开与收起；正在输入备注时，正文和事项外框必须在同一帧同步增减高度，不得让正文先变化、外框延迟追赶。
- 备注支持加粗和字体颜色，正文字号使用独立的 `15 px` 令牌，明显但不过度地大于普通事项正文；“备注 · 富文本”标题使用 `13 px` 正文字号。用户必须先选择一段文字，加粗按钮只切换所选范围；调色盘图标打开应用内调色盘，可用预设色或 RGB/CMYK 数值自定义，确认后只把颜色应用到所选范围。没有选择文字时不修改整段内容，并在底部给出提示。
- 编辑备注时禁止自动折叠或消失；输入过程只更新源数据和当前编辑缓冲，不得把每个字符经可见模型反向写回正在编辑的 `TextArea`，避免连续换行或删除时重置光标、选区或焦点。
- 输入、选字、打开下拉框、选择日期时间或文件时，不得被悬停离开逻辑折叠。
- 任一事项的名称、时间、状态或备注正在编辑时，鼠标悬停到其他事项只改变该事项的普通悬停高亮，不得切换或展开其备注，也不得释放当前编辑器的输入焦点。编辑通过 Enter、点击外部或控件自身提交结束后，如果鼠标仍停在另一事项上，必须从结束时刻重新等待完整的 240 ms 悬停延迟，再展开该事项备注；快速划过始终不展开。
- 搜索、事项名称、开始时间、完成时间、状态和备注等可编辑控件，在用户点击其边界之外且没有切换到另一个输入控件时必须释放输入焦点并隐藏文本光标；点击另一个输入控件时，焦点直接转移到新控件。可触发失焦的空白区域必须覆盖整个窗口，尤其包括事项卡之间、添加事项按钮下方以及没有事项时的列表视口空白，不得只在标题栏、信息栏或底栏生效。
- 已保存事件被编辑成名称为空、时间范围错误等无效状态时，不覆盖磁盘中的最后有效版本；界面保持错误状态并允许其他合法事件继续保存。
- 用户在仍有无效修改时切换页面或退出软件，必须询问“放弃修改 / 继续编辑”。选择放弃时恢复最后有效版本；选择继续时取消切换或退出，并把焦点与文本光标放到第一个错误字段。

### 6.5 添加事项

- 点击“添加事项”后立即显示可编辑事件组件。
- 可手动填写事项名称；名称为空时不得持久化。
- 新事项默认为一级事项，重要程度为 `5`，开始时间为当前本地时间，完成时间为空，项目状态为“进行中”。草稿固定显示在当前一级列表末尾，不参与活动排序，名称确认后再进入正常排序并使用重排动画移动到目标位置。
- 草稿处于输入焦点、中文输入法组合、下拉框/日期选择器/文件选择器打开、鼠标位于草稿区域或刚发生键盘输入时，必须保持显示。
- 当名称去除首尾空白后仍为空、鼠标已经离开草稿、名称输入框已经失去键盘焦点且连续 800 ms 没有输入时，才移除草稿并恢复“添加事项”按钮；名称框仍有键盘焦点、中文输入法正在组合或任一字段仍处于编辑状态时不得误删。名称输入框重新获得焦点必须立即停止已经运行的退出计时器。
- 同一时间只显示一个新事项草稿；草稿存在时隐藏“添加事项”按钮，草稿确认或自动移除后恢复按钮。
- 在新事项名称框按 Enter 时立即提交当前名称、释放输入焦点并隐藏文本光标；如果鼠标此时不在该事项整体区域内，随即收起该事项备注。名称为空时仍按空草稿规则处理，不写入 CSV。
- “添加事项”入口高度为紧凑的 34 px，中央同时显示独立 SVG 圆角方框加号图片和“添加事项”四个字；只保留这一组内容，不增加序号或其他重复入口。它不使用 Qt `Button` 的默认按下/焦点调色，悬停仅加强低对比背景和描边，文字始终保持清晰。

### 6.6 附件

- 每个事项支持多个附件，附件区位于备注内容上方。
- 附件按钮支持一次选择多个文件或文件夹；添加后横向显示 `32 px` 正方形缩略图，尺寸与附件按钮一致，面积约为原 26 px 方案的 1.5 倍。继续添加入口使用独立、清晰的“文件框 +”SVG 图片图标资源，不使用文本加号或与“添加事项”共用的图标；图标资源可按资源配置替换。
- 单一继续添加入口直接打开 Windows Shell 原生文件选择窗口，不显示应用自绘文件浏览器，也不先弹出“添加文件/添加文件夹”二级菜单。系统窗口允许一次多选文件，并在同一窗口提供“添加当前文件夹”按钮；用户进入目标目录后即可直接关联该目录。文件夹与普通文件共用 `attachments_json` 绝对路径数组，不新增 CSV 字段；目录路径保留结尾分隔符作为展示类型标记，以兼容既有文件附件。
- Windows 原生选择窗口打开期间必须固定当前事项的详情状态，并计入全局编辑门禁；取消或完成选择之前，备注区不得因鼠标离开事项而折叠，也不得触发待执行的自动排序。窗口关闭后的短暂展示期结束时，必须解除固定并立即重新判断鼠标与编辑状态；若鼠标已离开且没有编辑，按统一延时正常收起。
- 最后一个缩略图右侧始终显示继续添加按钮。
- 悬停或点击缩略图时显示附件名称，并在右上角显示删除按钮。
- 删除只解除附件路径关联，不删除磁盘原文件。
- 双击普通文件附件时调用 Windows 默认关联程序打开原文件，允许外部程序修改并保存。
- 文件夹附件显示可替换的文件夹 SVG 缩略图；双击文件夹附件时由系统文件管理器打开，单击只保留悬停/选中反馈，不立即打开。
- 只保存原文件绝对路径，不创建附件专属副本。
- 原文件移动、重命名或删除后，缩略图显示“文件不存在”状态；不得自动删除路径记录，并提供“重新定位”操作。
- 软件只缓存系统生成的缩略图，不缓存附件内容；缩略图缓存可以安全删除并重新生成。
- 当前主页面通过 Windows `IFileOpenDialog` 选择多个文件或当前目录，并把文件系统绝对路径随事件快照写回 CSV；原生窗口关闭前事项保持展开。文件夹已经使用专用图标，普通文件当前仍以扩展名小块代替系统缩略图，正式系统缩略图由后续 Windows 平台层接入。

### 6.7 删除事件

- 在事件整体组件区域任意位置右键打开与主界面相同石墨磨砂、圆角和模糊背景的上下文菜单；菜单提供“新建子事项”和“删除事项”。
- “新建子事项”创建一个以当前事项为父节点的空名称草稿，复用普通新增事项的名称、默认重要度、当前开始时间、取消空草稿和保存规则；同一时刻仍只允许一个新建草稿。
- 点击后必须显示确认提示：“删除该事件会将其所有子事件一并删除，请慎重选择。是否确认删除？”
- 用户确认后删除目标事件及完整子树；取消则不改变任何数据。
- 删除前创建可恢复的普通备份，删除和保存作为一个事务执行；附件仅解除引用，绝不删除磁盘原文件。

### 6.8 可替换资源

- 发行默认 Logo 位于安装目录 `assets/logos/default/`，允许包含多级子目录；同一逻辑 Logo 始终使用统一相对路径和文件名。
- 用户可新建与默认 Logo 目录结构一致的自定义文件夹，并编辑 `[InstallDir]/data/config/resources.json` 中 `logos.customRoot` 指向该目录；路径既可为安装目录相对路径，也可为绝对路径。
- `resources.json` 采用 `schemaVersion` 以及 `logos`、`icons`、`images`、`backgrounds` 四个分组；每组分别包含不可随意删除的 `defaultRoot` 和允许为空的 `customRoot`。`images.donationQr` 是打赏二维码的稳定资源键。所有相对根路径统一以安装目录为基准解析，禁止根据进程当前工作目录解析。
- 程序按“对应 `customRoot` 中的相对文件 → 对应 `defaultRoot` 中的相对文件 → 程序内应急资源”的顺序逐个解析；某个自定义文件缺失时只回退该文件，不使整个自定义目录失效。
- 首版在应用启动时加载 JSON；未来可通过 `reloadResources()` 接口实现设置页面即时刷新，无需改变业务组件。
- `resources.json`、自定义目录设置和安装目录内的 `data/customization/` 在更新、修复安装和默认卸载过程中保留。

## 7. 名人名言

- 名人名言存储在本地，不依赖网络，以哲学类名言为主，可包含黑格尔、毛泽东等作者。
- 首批离线库包含 1000 条，覆盖《周易》、孔孟典籍以及毛泽东、黑格尔、马克思、恩格斯、尼采等来源；数据文件需要版本号、总数、底本/许可清单和唯一 ID。
- 每条内容必须标明 `原文` 或 `意译`：原文使用可核验的公有领域短句，意译明确作为非逐字引文展示，不得伪装成原文直引。
- 启动时由 C++ 控制器校验 `schemaVersion`、`count` 和已核验记录后随机显示一条，手动刷新时避免与上一条立即重复；文件不可用或无有效记录时显示明确诊断并使用内置回退文本。
- 双击名言区域触发手动随机换句；名言正文与作者保持同一行。
- 主窗口可见且没有最小化时，每 2 分钟自动随机换句；窗口最小化或隐藏时暂停计时，恢复显示后重新开始完整的 2 分钟周期，不补播最小化期间错过的换句。
- 名人名言保持水平左对齐，只在垂直方向居中；组件不得在 `GlassPanel` 已提供的内容内边距之上重复增加顶部偏移。换句时旧内容从中心向下接近框底、缩小并淡出，新内容从框顶以较小比例出现、向中心落下并放大到正常尺寸；完整过渡约 720 ms，必须裁剪在名言圆角区域内并遵循全局“减少动画”开关。
- 默认窗口尺寸下，根据收录名言的实际长度确定固定显示宽度；录入前剔除必须低于正常字号 50% 才能完整显示的过长文本。
- 默认布局中文本过长时自动缩小字号，最小为正常字号的 50%。
- 短文本仍使用正常字号，不自动放大。
- 用户主动缩小窗口时不设置字号下限，可继续缩小直至文字不显示，不得挤动状态筛选框的固定位置。
- 每条名言必须保存正文、作者和可核验出处；来源不明或常见误传内容不得录入。

## 8. 数据保存与更新

### 8.1 安装与路径

- 使用 Qt Installer Framework 生成混合安装器与维护工具。安装器内含首装载荷，可离线完成首次安装；配置 HTTPS 仓库后，维护工具可在用户主动操作时访问 GitHub Pages 检查并安装更新。
- 安装器使用与主程序一致的紧凑石墨色系、圆角控件、青蓝高亮和中文界面；窗口基准为 1120×720，并在左侧显示当前流程步骤。首次安装依次展示欢迎、许可协议、安装位置、准备、进度和完成；维护流程统一覆盖更新、管理安装、卸载、完成和错误状态。
- 欢迎页必须明确“本地保存、支持分级事项、安全更新”；许可页的正文、同意复选框及禁用/启用状态必须具有足够对比度，复选框不得因主题覆盖而不可见；进度、错误原因和下一步建议必须使用同一视觉系统。
- 同时保留完全离线更新包：用户手动下载并解压本地仓库，由已安装维护工具通过临时 `file:///` 仓库执行。在线更新、离线更新和卸载均由安装目录内的 `ToDoItMaintenanceTool.exe` 承担，主程序不在后台自动检查或静默安装更新。
- 默认安装到当前用户可写的 `%LocalAppData%/Programs/ToDoIt`，并允许用户选择其他目录。
- 安装器选择目录后必须实际测试“创建、写入、重命名和删除临时文件”的权限；没有写权限时禁止继续并要求更换路径。
- Windows 的 `Program Files` 默认受 ACL/UAC 保护，普通进程通常不能修改安装目录，因此不能仅因为“用户选择了路径”就假定应用拥有写权限。本产品坚持相对安装路径保存数据，故默认采用每用户可写安装目录，不要求主程序以管理员权限运行。
- 运行时路径固定为：
  - `[InstallDir]/data/event.csv`：事件数据；
  - `[InstallDir]/data/config/settings.json`：用户配置；
  - `[InstallDir]/data/config/resources.json`：Logo、图标、打赏图片和背景资源根目录；
  - `[InstallDir]/data/backups/`：数据与配置备份；
  - `[InstallDir]/data/logs/update-history.jsonl`：更新历史；
  - `[InstallDir]/data/cache/thumbnails/`：可删除的附件缩略图缓存。

### 8.2 保存与备份

- 当前已接通 `event.csv` 启动读取与完整快照写回：有效的添加、右键新建子事项、字段编辑、备注格式、附件关联/解绑、右键删除完整子树、成为子事项、同级移动及移回一级会标记待保存；下一次 5 分钟脏检查或正常关闭会把删除后的完整快照原子写回。删除前普通备份与独立撤销/恢复事务仍未实现，不得宣称已具备可恢复删除。
- 有效编辑和拖拽完成后只设置待保存标记，不立即打开文件。单个 5 分钟计时器到期时先检查标记：没有修改则不打开、不写入；有修改才生成完整快照并保存。正常关闭前再次检查，只有仍有未落盘修改时才同步写入。保存失败时保留待保存标记并在底部显示错误；若启动加载失败则禁止写回，避免用空快照覆盖原数据。
- 每次保存先验证完整快照，再由 `QSaveFile` 在同目录写入 UTF-8 BOM、正式表头与 RFC 4180 记录，提交成功后原子替换正式文件；不启用非原子直接写入回退。
- 普通保存备份循环保留最近五份。
- 每次数据格式迁移前创建带旧软件版本、数据版本和时间戳的永久备份；自动清理不得删除迁移备份。
- 启动时若正式文件损坏，先停止自动写入，再提供从最近有效备份恢复的入口，禁止静默覆盖损坏文件。

### 8.3 在线/离线更新与迁移

- 更新包带有版本化清单，记录应用版本、事件格式版本、配置格式版本、增加/替换/删除的程序文件、文件哈希和迁移步骤。
- 更新前要求主程序退出并取得数据锁，然后备份 `event.csv`、`settings.json` 和旧版本清单。
- 更新器先在与正式文件同目录的临时候选文件中迁移数据，不直接流式覆盖正式文件。
- 迁移后至少验证：CSV 可完整解析、行数符合迁移预期、UUID 唯一、父 UUID 存在、父子图无环、字段约束有效、附件路径条目数未丢失、配置 JSON 可解析。
- 验证通过后提交新程序和新数据；任一步失败则回滚程序与数据，并保留失败日志和原始备份。
- 本地更新历史记录更新前后版本、变更文件、迁移器名称、迁移前后记录数与哈希、备份位置、开始/完成时间和结果，不记录备注正文等隐私内容。
- 更新时必须保留并迁移全部用户配置，包括窗口几何、筛选、搜索范围、排序组合、主题颜色/渐变/背景图设置等。
- 卸载默认保留整个 `data/`；只有用户主动勾选“同时删除我的事件、配置和备份”时才删除，并需二次确认。
- 0.1.0 是第一个正式数据架构，`eventSchema=1`，不存在可确认的更早发布格式；0.2.0 与 0.2.1 均继续使用同一事件架构，因此无需字段迁移。本版更新器仍对 v1 执行永久备份、正式仓储完整校验和前后 SHA-256 一致性检查；对无 `schema_version`、更高版本或缺少连续迁移声明的文件必须中止更新且不修改原文件，不允许根据相似列名猜测。
- 字段名是永久且大小写敏感的数据接口，发布后不得重命名。未来提高 `eventSchema` 时，新清单必须登记仍受支持的全部旧/新字段结构和逐级 `n → n+1` 迁移链。通用迁移器按精确同名字段复制旧值；新增字段使用目标架构清单的字符串缺省值；删除字段必须在相邻迁移的 `removedFields` 中显式列出后才丢弃。未声明字段消失视为可能误改名并阻止更新。
- 迁移候选必须由新版本正式仓储完整加载成功后才通过 `QSaveFile` 原子提交；安装状态写入失败时从迁移备份恢复。每次架构变更必须增加旧格式脱敏回归样例，仅修改清单数字不构成可发布迁移。
- GitHub Releases 保存安装器、离线更新包、在线仓库快照、清单、发布元数据和 SHA-256；GitHub Pages 只托管 Qt IFW 在线仓库。源码、构建产物与真实用户数据严格分离，发布步骤见 `docs/release.md`。

### 8.4 Qt 运行时打包

- Release 构建必须使用已验证的 Qt 6.11.2 `msvc2022_64` Kit、x64 MSVC 环境和 Ninja，禁止复用任何 MinGW 构建缓存。
- 正式流程优先使用 `qt_generate_deploy_qml_app_script()` 配合 `cmake --install` 生成暂存目录；同时可用 Qt 自带的 `windeployqt --dry-run --json` 审计部署内容。手工诊断时使用 `windeployqt --release --compiler-runtime --qmldir <QML源码目录>`。
- Windows 安装布局必须把 `ToDoIt.exe`、`ToDoItMigrator.exe`、`qt.conf` 与普通 `Qt6*.dll` 放在同一根目录；平台插件位于 `plugins/`，QML 模块位于 `qml/`。打包必须拒绝主程序在根目录但 Qt DLL 落入相邻 `bin/` 的布局，因为该安装包在未安装 Qt 的机器上无法启动。
- QWindowKit、外部 `assets/`、默认配置、迁移器、更新清单和许可证由项目打包脚本补充；`windeployqt` 不负责非 Qt 第三方库。
- 当前主界面直接使用 Qt Quick、Qt Quick Controls 2 和用于应用内弹层模糊的 Qt Quick Effects；附件选择使用 Windows SDK 自带的 Shell COM 接口，不新增 Qt Widgets 或 `Qt.labs.folderlistmodel` 运行依赖。部署审计必须包含 `QuickEffects` 运行模块及其平台插件/传递依赖。
- Qt SDK、头文件、静态库、示例、调试工具和编译器本体不得进入用户安装包。
- 暂存目录先在没有安装 Qt 的干净 Windows 10/11 环境运行冒烟测试，再交给 Qt Installer Framework 生成混合或纯离线安装包。
- 正式 GitHub 发行传入固定 HTTPS 更新地址并用 `binarycreator --hybrid` 生成混合安装器；它内含首次安装组件，同时把 GitHub Pages 仓库写入维护工具配置。`repogen` 生成的同一仓库还封装为离线更新 ZIP；离线脚本只把该目录作为本次维护进程的临时仓库。
- 在尚未购买 Qt 商业许可、也未要求公开 To Do It 全部源码的前提下，首版选择整体风险最低且可立即执行的 Qt 开源 LGPLv3 动态链接路线。只允许使用经许可证清单确认可在 LGPLv3 下使用的 Qt 模块；禁止无审查引入仅 GPL/商业许可模块。To Do It 应用本身可保持闭源，但必须完整履行 LGPLv3 义务。
- 每个发布包必须包含 LGPLv3 全文、Qt 使用声明、第三方版权清单、允许用户替换 Qt DLL 与运行替换版本的说明，并随包提供所用确切 Qt 版本及修改的完整对应源码，或由发布者控制且长期有效的书面获取方式；仅链接 Qt 官网不视为完成源码提供义务。
- 构建流程必须从 Qt 6.8+ SBOM 和实际部署目录生成依赖/许可证清单，并在打包阶段拒绝未知许可证、GPL-only Qt 模块、静态 Qt 库或缺失源码归档。
- 若未来无法完整履行 LGPLv3、需要限制用户替换/逆向调试，或要使用仅商业模块，则必须在继续相关开发或发布前取得有效 Qt 商业许可并完成许可迁移审查；不得在同一产品中混用开源 Qt 与商业 Qt。此处为工程合规约束，不替代专业法律意见。

## 9. 性能与可靠性

- 持续时间使用统一的一分钟计时器批量刷新，不为每个事件分别创建计时器；周期刷新直接更新可见模型中的持续时间字段，不重建、重排或写入 CSV。
- 首版按不超过 1000 个事件设计与验收。树筛选、实时搜索、多字段排序和统计由模型层批量计算后一次提交给界面。
- 保存采用临时文件写入、校验、替换的原子化流程，降低断电或崩溃造成 CSV 损坏的风险。
- 编辑状态与悬停状态分离，避免输入过程中组件折叠、消失或无法识别事项名称。
- 无边框/磨砂平台调用不得放在事件行渲染循环中；缩略图异步请求且限制并发，禁止阻塞 UI 线程。
- 筛选、搜索、拖拽、打开备注和输入文字的目标是无可感知卡顿；具体帧时间与启动时间指标在原型阶段实测后补充。
- 排序重排不得销毁并重新创建全部可见事项；应通过模型移动通知与位置动画更新，仅移动真正改变位置的委托。

- 用户确认的新需求应纳入本文。一次连续开发批次中先集中完成代码、配置和资源修改，全部程序文件完成后再统一更新一次 `docs/proposal.md` 与 `docs/structure.md`，并在交付前保证两份文档与最终文件状态一致；不得每修改一个文件就重复改写文档，也不得遗漏批次内的新增、删除、重命名或职责变化。
